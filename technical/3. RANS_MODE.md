## 1. Mode Classification & Philosophy

### 1.1 The Efficiency Principle (The "Header Tax" Trade-off)

Entropy coding (rANS) requires a Probability Density Function (PDF) per shard. SPX balances two strategies for providing it:

- **Custom Tailoring (Mode 0)**: Generates a pixel-perfect PDF from the exact shard residual histogram. Offers the lowest theoretical bit-cost but requires serialising the PDF table into the file header.
- **Ready-to-Wear (Modes 4–33)**: Uses one of 30 pre-baked empirical templates. Zero header cost, but may lose a small number of bits due to distribution mismatch.

**The Winning Logic**: If the bits lost from a template mismatch are fewer than the Mode 0 header cost, the template wins. The header cost is not a fixed constant — it scales with shard size (see §3.2).

### 1.2 Residual Encoding Space

SPX encodes residuals using **ZigZag mapping**:

```python
# Raw residual: (pixel - predicted) & 0xFF
# ZigZag maps small errors (near 0 or near 255) to small unsigned values
zigzag_symbol = to_zigzag(raw_residual)   # peak at 0, perfect prediction → 0
```

All PDF tables — both Mode 0 custom PDFs and the 30 empirical templates — operate in **ZigZag space**. The zero-residual (perfect prediction) maps to ZigZag symbol 0, which is always the most probable symbol in any shard.

> [!IMPORTANT]
> Templates must be stored in ZigZag space (peak at index 0). Center-shifted representations (peak at index 128) are incompatible with the rANS engine and cause the template system to degrade to 100% Mode 0 usage.

### 1.3 Available PDF Modes

| Mode ID | Category | Description | Header Overhead |
| :--- | :--- | :--- | :--- |
| **0** | **Custom Dynamic** | Pixel-perfect PDF built from exact shard histogram. | ~15–60 bytes (zstd-compressed with other shards) |
| **3** | **Zero-Entropy** | Flat distribution for empty or all-zero-residual shards. | 0 |
| **4–33** | **Empirical Templates** | 30 pre-baked static templates stored in the codec. | 0 |

> [!NOTE]
> Modes 1 and 2 are reserved for future use.

## 3. Decision Engine

### 3.1 Mode Routing

For each active shard the Rust selector (`decide_shard_mode` in `rans_core.rs`) applies this logic:

1. **Mode 3 (Zero-Entropy Bypass)**: If the shard contains only ZigZag symbol 0 (all residuals zero), assign Mode 3 immediately.
2. **Build custom PDF** from shard histogram (Mode 0 candidate).
3. **Evaluate all 30 templates** via cross-entropy against the shard histogram.
4. **Compare**: select the option with the lowest total cost (encoding bits + header cost).

### 3.2 Dynamic Penalty Gate

The Mode 0 header tax is not a fixed constant. It scales inversely with shard pixel count so that small shards — where the header is a large fraction of total bits — are penalised more aggressively, pushing them toward templates:

$$\text{Penalty}_\text{final} = 120.0 \times \frac{4096}{\max(n\_\text{pixels},\, 1)}$$

**Behaviour by shard size:**

| Shard Size | Penalty | Effect |
| :--- | :--- | :--- |
| ~10 pixels | ~49,152 bits | Mode 0 is prohibitively expensive → template always wins |
| ~500 pixels | ~983 bits | Template wins if fit is reasonable |
| ~4,096 pixels | 120 bits | Breakeven point |
| ~50,000 pixels | ~10 bits | Mode 0 costs essentially nothing → custom PDF dominates |
| >100,000 pixels | <5 bits | Mode 0 always wins unless template is near-perfect |

**Template selection condition**: template wins if and only if

$$\text{CrossEntropy}(\text{template}) < \text{CrossEntropy}(\text{custom PDF}) + \text{Penalty}_\text{final}$$

Additionally, if any symbol present in the shard has zero probability under the best template, Mode 0 is used regardless (impossible-symbol safety).

### 3.3 Mode 0 Serialization

When Mode 0 is selected, the PDF is serialized in the more compact of two formats:

1. **Dense (Internal ID 0)**: All probabilities up to `shard_width` as `uint16`. Cost: `width × 2` bytes.
2. **Sparse (Internal ID 1)**: Only non-zero symbols and their counts. Cost: `2 + (nonzero_count × 3)` bytes.

All Mode 0 PDF blocks across all shards are concatenated and Zstd-compressed together (level 3), which further reduces overhead by exploiting cross-shard correlation.

---

## 4. Protocol Constraints

- **Total Mass**: All PDF tables (custom and empirical) must sum exactly to **4096** (12-bit fixed-point). This allows the rANS engine to use bit-shifts instead of division.
- **Minimum Probability (Epsilon Rule)**: Any symbol present in a shard must have probability ≥ 1/4096. If a fitted PDF would assign 0 to an active symbol, SPX performs peak redistribution to grant it a probability of 1.
- **Alphabet Alignment**: Templates are clipped to `[0, shard_width − 1]`. Symbols outside this range are excluded to prevent bit-waste on unseen tails.
- **Coordinate Space**: All PDFs — Mode 0 and templates — must be in **ZigZag space** (peak at index 0). The `rans_mode.npz` file stores templates in this space.

## 5. Empirical Benchmark (Post-Fix)

The following results reflect the corrected template system (ZigZag-space templates + dynamic penalty).

### 5.1 Template Hit Rate by Dataset

Two hit-rate metrics are reported. **Observation hit rate** counts how often any shard/channel pair selects a template regardless of size. **Pixel-weighted hit rate** weights each observation by its pixel count — this is the compression-relevant metric because it reflects the fraction of actual data bytes affected.

| Dataset | Images | Obs Hit Rate | **Pixel-Weighted Hit Rate** |
| :--- | :---: | :---: | :---: |
| **Kodak** | 24 | ~14% | ~0.3% |
| **CLIC** | 182 | ~6% | ~0.1% |
| **DIV2K** | 100 | ~4% | ~0.1% |
| **Tecnick** | 40 | ~2% | ~0.1% |

The gap between observation hit rate and pixel-weighted hit rate is explained in §6.

### 5.2 Compression Improvement from Fixes

Measured against a Mode-0-forced baseline (both fixes disabled):

| Dataset | Savings | Relative Gain |
| :--- | :--- | :--- |
| Kodak | ~10 KB / 24 images | 0.089% |
| CLIC | ~30 KB / 182 images | 0.006% |
| DIV2K | ~12 KB / 100 images | 0.004% |
| Tecnick | ~2 KB / 40 images | 0.001% |

The improvement is universal (never harmful) but modest, because Mode 0 header overhead is negligible for large shards: the entire Mode 0 PDF block per image is Zstd-compressed together, and at large pixel counts the dynamic penalty per symbol approaches zero.

## 6. Large-Scale Template Derivation Study

### 6.1 Setup

To determine whether better-fitted empirical templates would improve compression, a corpus-scale k-means clustering study was conducted over the complete available image set.

**Corpus**: 1,913 images across all unique datasets (DIV2K Train+Val, CLIC 2017/2021/2022/2024/2025, Kodak, Tecnick). The DIV2K Easy/Gold/Hard/Hell subsets were excluded as duplicates of DIV2K Train.

**Method**: Every image was compressed with `use_bitplane=False` to expose `shard_stats` (per-shard ZigZag residual histograms). Each active (image, channel, shard) triple was normalised to a probability distribution. Scipy k-means was then run on the pooled 236,804 observations for k ∈ {10, 20, 30, 40, 50, 60, 80, 100} with 5 random restarts each. Centroids were quantised to 12-bit fixed-point templates and evaluated against both the dynamic Rust penalty and the correct fixed 120-bit penalty.

### 6.2 Results

| k | Dyn obs% | **Dyn wpx%** | Fix obs% | **Fix wpx%** | Δ Dyn wpx | Δ Fix wpx |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **bsl (30)** | 10.2% | **0.2%** | 7.5% | **0.2%** | — | — |
| 10 | 7.5% | 0.1% | 3.4% | 0.0% | −0.1 pp | −0.2 pp |
| 20 | 7.8% | 0.1% | 3.7% | 0.0% | −0.1 pp | −0.2 pp |
| 30 | 8.0% | 0.1% | 3.9% | 0.0% | −0.1 pp | −0.2 pp |
| 50 | 8.2% | 0.1% | 4.1% | 0.0% | −0.1 pp | −0.2 pp |
| 100 | 8.3% | 0.1% | 4.3% | 0.0% | −0.1 pp | −0.2 pp |

Every k-means configuration is **worse than the current 30 hand-tuned templates** on the pixel-weighted metric. Increasing k from 10 to 100 yields no meaningful improvement.

### 6.3 Root Cause: Pixel Count vs Penalty Mismatch

The penalty formula `120 × (4096 / n)` was designed assuming ~4096 pixels per shard. Actual shard pixel counts in the corpus are far larger:

| Shard group | Avg pixels / obs | Template wins (fixed 120 b) if overhead < |
| :--- | :---: | :---: |
| Shards 0–2 (dominant) | 181,000–216,000 | 0.00066 b/sym |
| Shards 5, 8, 17 (large) | 120,000–140,000 | 0.00086–0.00100 b/sym |
| Shards 9, 10, 18, 19 (medium) | 12,000–15,000 | 0.0080–0.010 b/sym |
| Shards 27, 28 (smallest) | 11,700–11,850 | 0.010 b/sym |

The 120-bit Mode 0 header is a fixed cost regardless of shard size. The template mismatch cost scales linearly with n: even a tiny overhead of 0.001 b/sym × 120,000 pixels = 120 bits — right at the break-even point. For the large shards that dominate this corpus, template overhead must be sub-millibits per symbol to win, which no real distribution template achieves.

**Example**: Shard 0 (avg 182,356 pixels). A template with just 0.002 b/sym overhead costs 365 bits in mismatch — 245 bits more than Mode 0's fixed 120-bit header. The break-even overhead is 120 / 182,356 = 0.00066 b/sym, a level of distribution accuracy no pre-baked template achieves in practice.

### 6.4 Why Observation Hit Rate Is Misleading

The 10–14% observation hit rate seen on small datasets (Kodak) is driven entirely by rare small shards (n ≈ 4,096 or less) where the dynamic penalty is artificially inflated. These shards contain a negligible fraction of total pixels. The pixel-weighted hit rate — 0.2% across all datasets — is the accurate measure of compression impact.

### 6.5 Conclusion

**The template system (Modes 4–33) has near-zero impact on compression for typical HD/2K images.** The bottleneck is structural, not a matter of template quality:

1. Better k-means centroids do not help — the current 30 hand-tuned templates marginally outperform all k-means solutions.
2. More templates (up to k=100) do not help — marginal gains plateau immediately.
3. The penalty formula and Mode 0's Zstd-compressed PDF block make Mode 0 essentially free for large shards.

**Viable paths forward:**
- **Remove templates** — simplify the system; Mode 0 is dominant (>99.8% wpx) with no loss.
- **Parametric lightweight coding** — replace the 120-bit custom PDF with a 1–2 parameter model (e.g., quantised mean + shape) that costs 8–16 bits. This would reduce Mode 0 overhead, not introduce templates, and benefit all shard sizes.
- **Accept current state** — the template system is harmless and may provide marginal gains on small images (< 512 × 512 at typical shard densities).

## 7. Parametric Mode Investigation (Geometric)

A controlled experiment evaluated whether adding single-parameter geometric modes could reduce Mode 0 header overhead.

**Model**: A geometric distribution in ZigZag space `P(z) = q(1−q)^z` fitted via MLE from the shard histogram mean (`q = 1/(1 + mean_zigzag)`). Storage cost: 8 bits (1 byte for quantised q) vs 15–60 bytes for Mode 0.

**Result across 346 images (CLIC + Kodak + DIV2K + Tecnick), all 42 shards**:

| Entropy Band | Shards | Geo Wins | Avg Fit Overhead | Avg KL |
| :--- | :---: | :---: | :---: | :---: |
| Low (H < 2 bits) | 6 | 0 | +0.168 b/sym | 0.117 |
| Mid (2–4 bits) | 24 | 0 | +0.118 b/sym | 0.082 |
| High (H > 4 bits) | 12 | 0 | +0.187 b/sym | 0.130 |
| **All shards** | **42** | **0** | **+0.154 b/sym** | **0.107** |

**Conclusion**: Geometric modes are not viable. ZigZag residuals have visible asymmetries and non-geometric tails (particularly shards 39–41 with KL ≈ 0.30–0.48) that a single-parameter model cannot capture. The 0.07–0.70 bits/symbol fit overhead exceeds any header savings by a wide margin, even for the smallest shards. The existing template system (which imposes zero fit overhead when a template is chosen) is the correct mechanism for small-shard PDF overhead reduction.

## 8. Developer Notes

### 8.1 Template Coordinate Space (Critical)
Templates in `rans_mode.npz` must be in **ZigZag space**. To convert a center-shifted histogram (peak at 128) to ZigZag space:

```python
zz_to_center = np.zeros(256, dtype=np.int32)
for z in range(256):
    s = z // 2 if z % 2 == 0 else -((z + 1) // 2)
    zz_to_center[z] = np.clip(s + 128, 0, 255)

template_zz = template_center_shifted[:, zz_to_center]   # re-index columns
```

### 8.2 Debugging Environment Variables

- `SPX_DISABLE_TEMPLATES=1`: Forces Mode 0 for all shards. Use to establish a pure-entropy baseline or isolate template impact.

### 8.3 Alpha Channel
The alpha channel is excluded from the rANS mode system. Alpha residuals are compressed directly with Zstd level 1 due to their typically sparse or binary character.
