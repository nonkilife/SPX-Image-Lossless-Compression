## 1. Mode Classification & Philosophy

### 1.1 The Efficiency Principle (The "Header Tax" Trade-off)
Entropy coding (rANS) saves space by assigning shorter codes to frequent symbols. This requires a Probability Density Function (PDF). 

**Residual-Based Modeling**:
SPX does not encode pixels directly. Instead, it encodes the **Predictive Residuals** (the error between the MED predictor and the actual pixel). 

- **Centered Storage**: Residuals are normalized to the `uint8` range [0, 255] using a **Modular Center-Shift of 128**:
  ```python
  encoded_symbol = (actual_pixel - predicted_value + 128) & 0xFF
  ```
  - **Modular Folding**: While raw residuals ($actual - pred$) range from -255 to +255, SPX utilize 8-bit wrap-around arithmetic (`& 0xFF`). This "folds" the 511 possible error states into 256 cyclic states. In this circular space, a large negative error (e.g., -255) is statistically treated as a small positive deviation (+1).
  - **Mapping**: A zero-residual maps to the center (**128**). Small errors cluster near 128, while catastrophic prediction failures reside at the boundaries (0 and 255).
  - **Symmetry**: This ensures the PDF peak is always centered at 128, allowing the 30 empirical templates to model symmetric "bell-shaped" distributions without complex branching or ZigZag LUTs.

**The Balancing Act**:
Since no two images have identical distributions, SPX balances two strategies:
- **Custom Tailoring (Mode 0)**: Generates a pixel-perfect PDF for a specific shard. It offers the **lowest theoretical bit-cost** but requires storing the PDF table in the file header (**Header Tax: ~120 bits**).
- **Ready-to-Wear (Modes 4-33)**: Uses pre-baked templates. While a template may be a "slightly ill fit" (mismatch loss), it is **header-free**. 

**The Winning Logic**: If the bits lost due to a "slightly ill-fitting" template are fewer than the ~120 bits needed to store a custom table, the template is selected. This is why small shards (where 120 bits is a large percentage of total data) favor empirical modes.

**The Inverse Selection Rule**: 
There is a direct inverse relationship between the Mode 0 Tax and Template Adoption:
- **Low Tax Environment**: Mode 0 becomes cheap, discouraging template use even when templates are reasonably accurate.
- **High Tax Environment**: Mode 0 becomes prohibitively expensive, forcing the encoder to adopt templates even if the fit is mediocre.
Effective BPP optimization relies on making templates accurate enough to "underbid" the Mode 0 cost at its realistic physical tax level (~120 bits).

### 1.2 Available PDF Modes
| Mode ID | Category | Description | Header Overhead |
| :--- | :--- | :--- | :--- |
| **0** | **Custom Dynamic** | Perfectly fitted PDF generated from exact shard counts. | High (~15-60 Bytes) |

## 2. Empirical Templates (Modes 4-33)

To eliminate the "Header Tax" for common image patterns, SPX stores 30 pre-calculated probability distributions. These templates were derived via K-Means clustering of 6,185 real image shards.

### 2.1 The 6x5 Matrix Structure
The 30 modes are generated by combining **6 Base Centroids** with **5 Sigma Scales**.

- **6 Centroids (C0 - C5)**: Represent unique statistical profiles captured from cluster analysis:
    - **C0: Generic Photographic**: The balanced "Laplacian-like" distribution typical of natural scenes.
    - **C1: Ultra-Sharp / Flat**: A distribution with a massive peak at 128; optimized for constant-color areas or extremely simple gradients.
    - **C2: Moderate Smooth**: A softer peak with gradual decay, ideal for soft-focus areas or low-contrast textures.
    - **C3: High-Energy Detail**: A distribution with a thickened base, capturing shards with significant high-frequency detail.
    - **C4: Granular / Noise**: A very wide, flat-topped distribution optimized for sensor noise, film grain, or chaotic foliage.
    - **C5: Adaptive / Complex**: A unique hybrid distribution shaped by edge-cases where the MED predictor produces inconsistent residuals.
- **5 Scales (S0 - S4)**: Scaling factors `[0.5, 0.75, 1.0, 1.25, 1.5]` that control distribution "sharpness" (variance):
    - **S0 (0.50): Ultra-Sharp**: Compressed variance; gives maximum savings for extremely accurate predictions (e.g., synthetic UI, low-noise RAW).
    - **S1 (0.75): Sharp**: Slight compression of the base centroid for high-fidelity edges.
    - **S2 (1.00): Standard**: The original statistical distribution from image clustering.
    - **S3 (1.25): Wide**: Expands the distribution to better accommodate moderate noise or complex gradients.
    - **S4 (1.50): Ultra-Wide**: Maximum expansion; prevents "entropy explosion" in shards with high variance or poor predictability (e.g., ISO noise, chaotic foliage).

### 2.2 Mode Mapping Logic
The Mode ID is calculated based on the nested loop in `core/common.py`:
```python
# For each scale in [0.5, 0.75, 1.0, 1.25, 1.5]:
#     For each base centroid in P_LIST:
#         Generate Final Template
```
**Formula:** `Mode_ID = 4 + (Scale_Index * 6) + Centroid_Index`

## 3. Decision Engine (rans_selector)

The `decide_shard_mode` logic in `core/rans_selector.py` handles the trade-off between mathematical precision and physical metadata cost.

### 3.1 Cost-Benefit Analysis (Mode Routing)
For every active shard, the selector determines the optimal encoding strategy by evaluating cross-entropy against available models:

1. **Mode 3 (Uniform/Empty Bypass)**: If a shard contains zero pixels (unseen context) or consists entirely of zero-residuals, it is assigned Mode 3. This bypasses the search engine and uses a hardcoded zero-entropy PDF.
2. **Mode 0 vs. 4-33 Evaluation**:
    - **$C_{optimal}$**: The cross-entropy of the shard using a custom-fitted PDF (Mode 0).
    - **$C_{template}$**: The cross-entropy of the shard using the best-fitting Empirical Template (Mode 4-33).

### 3.2 The Penalty Gate (Pixel-Adaptive Logic)
The selector uses an aggressive penalty mechanism to determine if the Mode 0 "Header Tax" is worth paying.

- **Base Penalty**: **120 bits** (approx. 15 bytes), representing the minimum serialization cost of a custom PDF.
- **Dynamic Scaling Formula**:
  $$Penalty_{final} = 120.0 \times \left( \frac{4096}{\max(n\_pixels, 1)} \right)$$
- **Behavior**:
    - **Small Shards (e.g., Kodak)**: The penalty scale increases exponentially. A 100-pixel shard faces a ~4900 bit penalty, making it nearly impossible to select Mode 0, thus forcing the use of **Empirical Templates**.
    - **Large Shards (e.g., DIV2K)**: The penalty stabilizes near 120 bits. The high pixel count makes the 15-byte tax negligible compared to the 0.01 BPP gains from a custom PDF, favoring **Mode 0**.

### 3.3 Mode 0 Serialization (Header Storage)
When Mode 0 is selected, the PDF table is saved using one of two internal formats to minimize the "Header Tax":
1. **Dense Format (Internal ID 0)**: Stores all probabilities as `uint16` up to `shard_width`. Cost: `width * 2` bytes.
2. **Sparse Format (Internal ID 1)**: Stores only non-zero symbols and their counts. Cost: `2 + (nonzero_count * 3)` bytes.
The encoder (`core/rans.py:compact_pdf_tables`) automatically selects the leanest format per shard.

## 4. Technical Design Specification (Hybrid Elite V10)

This section defines the normative architecture for the SPX v7.3.x template system, intended for downstream implementation.

### 4.1 Core Artifacts
- **Centroid Data**: Directly embedded in **Section 8** of this manual.
  - **Format**: 10 Integer Arrays (Length 256). Each array encodes a Probability Density Function centered at 128 with a total mass of 4096.
  - **Composition**: 7 Categorical Shapes + 3 Universal K-Means centroids.

### 4.2 Matrix Configuration
- **Matrix Dimensions**: 10 Centroids × 3 Scales = **30 Empirical Modes**.
- **Intensity Scales**: `[0.5, 1.0, 1.5]`
  - `0.5`: Wide distribution (High variance/noise).
  - `1.0`: Standard distribution (Native statistical captured frequency).
  - `1.5`: Sharp distribution (Ultra-low residual focus).

### 4.3 Mapping & Generation Logic
- **Mode ID Mapping**: 
  - Starting Index: **4** (Modes 0-3 Reserved).
  - Formula: `Mode_ID = 4 + (Scale_Index * 10) + Centroid_Index`
- **Normalization Requirements**:
  - All generated templates must be strictly centered at **128**.
  - **Total Mass**: Exactly **4096** (12-bit fixed point precision).
  - **Epsilon Rule**: Minimum probability of `1/4096` for all active symbols.

### 4.4 Decision Mechanism (Hedge Logic)
- **Mode 0 Penalty (Tax)**: Fixed at **120 bits**.
- **Selection Criteria**: A template (Mode 4-33) is selected if and only if:
  $$Entropy(Template) < Entropy(Custom PDF) + 120.0$$
- **Target Optimization**: Maximizing hit rates in small-shards where the 120-bit overhead is prohibitively expensive.

## 5. Protocol Constraints

- **Total Mass**: All PDF templates (Custom and Empirical) must sum exactly to **4096** (12-bit precision). This allows the rANS engine to use bit-shifts instead of division for state updates.
- **Minimum Probability**: Per the "No-Zero Rule", any symbol present in a shard must have a probability of at least **1/4096**. If a perfectly fitted PDF results in a 0% entry for an active symbol, SPX performs "Peak Redistribution" to grant that symbol a probability of 1.
- **Alphabet Alignment**: Templates are strictly limited by the `shard_widths` detected in Pass 1. Symbols outside `[0, width-1]` are strictly prohibited from the PDF to prevent bit-waste.

## 7. Developer's Technical Notes

### 7.1 The Alpha Channel Exception
The Alpha channel is **EXCLUDED** from the rANS Mode Matrix. 
- **Rationale**: Alpha residuals are often sparse or binary (0/255). 
- **Implementation**: SPX uses a direct **Zstd compression** layer for Alpha residuals to maintain high encoding throughput. 

### 7.2 Debugging Environment Variables
Developers can override the `rans_selector` decision logic for characterization:
- `SPX_DISABLE_TEMPLATES=1`: Forces the codec to use **Mode 0 (Custom)** for all shards. This is useful for finding the "Pure Entropy" baseline of a dataset.
- `SPX_REPORT_MEDIAN=1`: Enables console logging of median-shifting effectiveness during Pass 1.
