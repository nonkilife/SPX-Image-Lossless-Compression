# SPX Predictor Analysis: MED Logic & Hit Rate

This document records the statistical performance of the **Median Edge Detector (MED)** predictor within the SPX codec. These metrics are derived from a full-set analysis of the CLIC dataset to understand spatial redundancy and predictor limitations.

## 1. Dataset & Analysis Scope
- **Samples**: 182 high-resolution PNG images (CLIC Dataset).
- **Total Pixels Analyzed**: 1,518,131,826 (approx. 1.51 Billion).
- **Target Channels**: G (Green Leader), RD (Red-diff), BD (Blue-diff) after G-sub RCT.
- **Hit Definition**: Residual error |P - pred| <= 2.

### 1.1 Neighbor Copy Hit Rate (Passive Answer Availability)
This baseline measures the **statistical probability** that the correct pixel value P already exists within the immediate causal neighborhood (a, b, or c). In this context, neighbors are treated as a **predefined pool of answer candidates**.

- **Significance**: If P == {a, b, c}, the ideal predictor should simply "select" the matching neighbor rather than calculate a new value.
- **Baseline**: The 56.30% Exact Hit rate represents the theoretical maximum efficiency for any predictor that solely relies on neighbor selection (Copy Mode).

| Range | Hit Condition | Incremental % | Cumulative % |
| :--- | :--- | :--- | :--- |
| **Exact Hit** | P == a OR P == b OR P == c | **56.30%** | 56.30% |
| **PM1 Hit** | |P - {a,b,c}| == 1 | **21.63%** | 77.93% |
| **PM2 Hit** | |P - {a,b,c}| == 2 | **7.71%** | 85.64% |
| **PM3 Hit** | |P - {a,b,c}| == 3 | **3.91%** | 89.55% |
| **PM4+** | |P - {a,b,c}| >= 4 | **10.45%** | 100.00% |

#### Selection Efficacy Analysis:
- **MED Selection Accuracy (73.50%)**: When a correct answer exists in the neighbor pool (56.30% of total pixels), MED successfully selects it 73.50% of the time.
- **Independent Prediction Rate (1.92%)**: Cases where no neighbor is correct, but MED's formula (a + b - c) achieves an exact hit.
- **Optimization Gap (14.92%)**: The "Missed Opportunity" where a valid neighbor existed, but MED failed to identify it, leading to a non-zero residual.

### Column Legend & Definitions
The following metrics are used across sections 2.1 to 2.4 to evaluate predictor efficiency:

- **Diff (|a - b|)**: The absolute difference between Left (a) and Top (b) neighbors. Measures local context volatility.
- **Occ % (Occurrence)**: The percentage of total branch pixels that fall into this specific difference bin.
- **Z% (Hit=0)**: The probability that the predicted value exactly matches the target pixel (Residual = 0). **Highest priority for rANS efficiency.**
- **H<=1**: The probability that the residual magnitude is <= 1.
- **H<=2**: The probability that the residual magnitude is <= 2.
- **MAE (Mean Absolute Error)**: The average magnitude of the residual. Measures the "cost" of prediction failure.

### 2.5 High-Gradient Selection Inversion (The Flip Point)
Empirical analysis reveals that the standard MED selection logic (min for C1, max for C2) becomes statistically sub-optimal in the presence of extreme spatial gradients.

- **The Discovery**: When the distant neighbor (c) creates a "Step Jump" (> 50 units) relative to the local neighbors (a, b), the target pixel P is significantly more likely to follow the neighbor **closer to C** rather than the MED-prescribed fallback.

#### Flip Ratio (Inverse Selection vs Baseline) at Jump > 50:
The ratio represents how much more likely the "Wrong Neighbor" (according to MED) is an **Exact Match** compared to the "Right Neighbor".

| Local Diff (|a-b|) | Case 1 Inversion Ratio | Case 2 Inversion Ratio |
| :--- | :--- | :--- |
| **Diff 1** | 1.16x | 1.40x |
| **Diff 2** | 2.01x | 2.06x |
| **Diff 3** | **2.48x** | **2.42x** |

#### Proposed "Edge-Tuned MED" Logic (v7.3.0 Candidate):
```python
# Unified Edge-Tuned Logic
if c >= max(a, b):
    if (c - max(a, b) > 50) and (abs(a - b) <= 3):
        return max(a, b) # Follow the jump
    return min(a, b)
elif c <= min(a, b):
    if (min(a, b) - c > 50) and (abs(a - b) <= 3):
        return min(a, b) # Follow the jump
    return max(a, b)
```
- **Strategic Value**: This logic specifically targets the "Extreme Edge" scenarios where MED traditionally underperforms, converting potential large residuals into Zero Hits concurrently with lowering MAE in those regions.

### 2.6 Contextual Adjustment (ADJ) Matrix
Beyond simple neighbor selection, statistical analysis reveals consistent numerical biases in local contexts. These biases can be corrected using a small integer adjustment (**adj** in range [-2, 2]).

- **The Discovery**: In smooth regions where $c = max$ (**Jump 0**), pixels exhibit "Numerical Gravity," leaning 1 unit away from the extreme MED prediction towards the neighborhood average.
- **Extreme Bias**: In very high gradient Case 2 regions with local Diff 2, the prediction error is systematically shifted by **-2** units.

#### Top Contextual ADJ Rules:
The following contexts provide the highest net increase in Zero-Hit frequency (extrapolated per 250M pixels):

| Branch | Diff | Lead | Jump | **ADJ** | **Gain (Hits)** | **Z% Increase** |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **C2** | 1 | Horiz | 0 | **-1** | **137,598** | **+1.61%** |
| **C1** | 1 | Horiz | 0 | **+1** | **73,736** | **+0.86%** |
| **C1** | 2 | Horiz | 0 | **+1** | **24,217** | **+0.84%** |
| **C2** | 2 | Horiz | 0 | **-1** | **24,019** | **+0.84%** |
| **C2** | 2 | Vert | 51+ | **-2** | **5,099** | **+9.47%** |

- **Total Predicted Volume Gain**: ~287,000 additional Zero-Hits per 250M pixels analyzed.
- **Implementation Strategy**: Integrating these rules into a compact **Look-Up Table (LUT)** allows the predictor to capture complex spatial trends without significant computational overhead.

#### Lean-ADJ Implementation (Numerical Gravity):
```python
# Context-Adaptive Lean Adjustment
if c >= max(a, b):
    p = min(a, b)
    if (c == max(a, b)) and (abs(a - b) <= 2) and (a > b):
        return p + 1 # Gravity pull towards Horizontal
    return p
elif c <= min(a, b):
    p = max(a, b)
    if (c == min(a, b)) and (abs(a - b) <= 2) and (b > a):
        return p - 1 # Gravity pull towards Horizontal
    return p
```

### 2.7 Layered Adaptive Toggle (v7.3.0 Final)
To prevent regressions on ultra-clean imagery (e.g., Tecnick), the predictor uses a two-tier activation strategy based on Pass-1 statistics.

- **Edge-Tuning**: Always Enabled.
- **Lean-ADJ**: Adaptive. Disabled if **Base Z-Hit Rate > 35%**.

#### Integrated Adaptive Logic:
```python
@njit(cache=True)
def med_v730_final(a, b, c, enable_adj):
    max_ab, min_ab = max(a, b), min(a, b)
    diff = abs(a - b)
    
    if c >= max_ab: # Case 1
        p = min_ab
        jump = c - max_ab
        if jump > 50 and 1 <= diff <= 3: return max_ab # Always active
        if enable_adj and jump == 0 and diff <= 2 and a > b:
            return p + 1 # Dynamic pull context
        return p
    elif c <= min_ab: # Case 2
        p = max_ab
        jump = min_ab - c
        if jump > 50 and 1 <= diff <= 3: return min_ab # Always active
        if enable_adj and jump == 0 and diff <= 2 and b > a:
            return p - 1 # Dynamic pull context
        return p
    else:
        return a + b - c
```

### 3.5 Strategic Architecture Analysis

#### 2. The Case 3 Fallout

- **Strategic Implementation**: While MED v7.3.0 handles Case 1 & 2, **Sharding** will be used to isolate Case 3 pixels (identified by the logic-gate fallback). This allows for specialized probability models for these 18.25% of pixels without impacting the predictor's core speed.

### 3.6 v1.0.0 Branchless Migration & High-Precision Verification
In April 2026, the `med_edge_tuned` kernel underwent a critical refactor to eliminate branching and leverage SIMD execution paths.

#### 1. Branchless Migration Logic
The conditional logic was replaced with boolean arithmetic to prevent pipeline stalls:
```python
is_smooth = (diff >= 1) & (diff <= 3)
is_high = ci > (max_ab + 50)
is_low = ci < (min_ab - 50)
res = p + is_smooth * (is_high * (max_ab - p) + is_low * (min_ab - p))
```

#### 2. Performance Re-Verification (v1.0.0)
The migration resulted in a significant throughput increase across all target architectures:
- **Core Kernel Speedup**: **~30.4%** (Micro-benchmark).
- **Overall System Throughput**: **+9% to +34%** gain depending on dataset complexity (TRGB/TGRAY seeing highest gains).

#### 3. High-Precision Compression Impact (Bytes)

## 4. Methodology
The v7.3.0 optimization suite was developed through a systematic four-phase research pipeline:

1.  **Contextual Bias Scanning**:
    Using `research/med_adj_optimizer.py`, we performed a multi-dimensional scan of prediction residuals across all MED branches. This identified "Numerical Gravity" (systematic offset) in smooth regions and "Selection Inversion" in high-gradient boundaries.

2.  **Adaptive Toggle Design**:
    Based on the discovery of the "Tecnick Anomaly," we implemented an image-level logic gate. The system uses a Pass-1 Hit-Rate scan (>35% threshold) to identify high-precision industrial data, automatically toggling the ADJ logic to prevent over-correction.

3.  **High-Performance Re-engineering**:
    To overcome the 6.31% branching overhead, we performed a micro-benchmark race (`research/med_v730_race.py`). This led to the discovery of the **Branchless Arithmetic** pattern, which leverages LLVM's SIMD pipelining to increase performance by 9.16%.

4.  **Hardware & Tools**:
    - **Architecture**: RCT (Green-Subtract) -> Branchless Adaptive MED (v7.3.0).
    - **Acceleration**: Numba-JIT targeting x86-64 / ARM NEON SIMD lanes.
    - **Validation**: Entropy-based savings analysis across the unified SPX Benchmark suite (1.5B test pixels).
